# Xiaohongshu Content Guide

## Tone

- Warmer and more approachable than Twitter, but still composed
- Scenario-driven: "today Anna helped me..." or "this is what it feels like to..."
- Speak like a thoughtful person sharing a genuine workflow discovery
- Never like a sales account or tech influencer
- Simplified Chinese (简体中文) only

## Format

Every post follows this structure:

```
标题: <title — under 20 characters, with 1-2 emoji as hooks>

正文:
<2-4 short paragraphs, conversational but clear>
<Each paragraph 1-3 sentences>
<End with a takeaway or invitation to try>

标签: #tag1 #tag2 #tag3 #tag4
```

### Title Rules

- Keep under 20 characters (Chinese)
- Use 1-2 emoji at the beginning or end as visual hooks
- State the scenario or benefit directly
- No clickbait, no ALL CAPS energy

Good titles:
- "终端聊到一半，手机上继续 📱"
- "让 AI 记住你的工作习惯 🧠"
- "一个二进制文件搞定 AI 助手 ⚡"
- "Anna 帮我追踪了一周的进度 📋"

Bad titles:
- "震惊！这个AI助手太强了！！" (clickbait)
- "Anna v0.5.2 更新日志" (release notes)
- "最好用的AI工具推荐" (generic listicle)

### Body Rules

- Open with a concrete scenario or problem, not a product introduction
- Show the experience, not the feature list
- Use short paragraphs (1-3 sentences each)
- End with a natural takeaway — not a hard CTA
- Acceptable closing patterns: reflection, invitation to try, or a simple statement of value

### Hashtag Rules

- 3-5 hashtags per post
- Mix product-specific and discovery tags
- Common tags: `#AI助手`, `#本地部署`, `#效率工具`, `#自托管`, `#开发者工具`, `#工作流`, `#Anna`
- Never use unrelated trending tags

## Content Patterns by Pillar

### Anna can do this

Frame the capability as a personal experience. Show, don't list.

Good:
```
标题: 终端聊到一半，手机上继续 📱💻

正文:
早上在终端问 Anna 帮忙整理项目文档结构，聊到一半出门了。

中午在 Telegram 上跟她说「继续刚才的」，她直接接上了——不用重新解释背景，不用粘贴上下文。

这种跨设备的连续感，用过就回不去了。

标签: #AI助手 #本地部署 #效率工具 #工作流 #Anna
```

Bad:
- Listing features without a scenario
- "Anna 支持终端、Telegram、QQ、飞书四个渠道" (spec sheet)

### Built Anna today

Share a specific decision with enough context for non-engineers to understand.

Good:
```
标题: 为什么 Anna 选择本地 SQLite 🗄️

正文:
很多 AI 产品把数据存在云端，你换个设备就要重新登录，数据在别人服务器上。

Anna 用的是本地 SQLite——一个文件搞定所有对话记录和记忆。备份就是复制文件，迁移就是拷贝过去。

简单的方案往往最可靠。

标签: #本地部署 #自托管 #开发者工具 #Anna #SQLite
```

### Memory is a feature

Focus on the feeling of being remembered, not the technical mechanism.

Good:
```
标题: 让 AI 记住你说过的话 🧠

正文:
上周跟 Anna 讨论了项目的认证方案，今天直接问她「上次我们定的 JWT 方案是什么来着？」

她完整地回忆出来了——包括我提到的密钥轮换周期。

大部分 AI 聊完就忘，Anna 不会。这就是长期记忆的意义。

标签: #AI助手 #长期记忆 #效率工具 #Anna #工作流
```

### Local-first assistant

Speak to the feeling of control and simplicity, not technical paranoia.

Good:
```
标题: 一个文件，跑起来就是 AI 助手 ⚡

正文:
不需要 Docker，不需要注册账号，不需要把数据交给第三方。

下载一个 Go 二进制文件，配置好 API key，终端里敲 `anna chat` 就能用。

对话数据全在本地，想备份就复制文件夹。简单到没什么好说的。

标签: #自托管 #本地部署 #开发者工具 #AI助手 #Anna
```

### Anna in daily life

Paint a small but relatable daily moment.

Good:
```
标题: Anna 下午三点提醒我检查部署 ⏰

正文:
早上在终端设了个提醒：「下午三点看一下 staging 环境」。

三点的时候 Telegram 弹了条消息，是 Anna 发的。

没有多余的废话，就是准时提醒。而且她知道我说的是哪个项目——因为上下文还在。

标签: #AI助手 #效率工具 #工作流 #Anna #提醒
```

### Designing Anna

Share design thinking in an accessible way. People love behind-the-scenes.

Good:
```
标题: 给 AI 助手设计一张脸 🎨

正文:
Anna 的头像不是随便找的素材图。我们定了一个方向：70% 真人感，30% 品牌感。

她应该看起来像真实存在的人，但不会被误解成某个真人博主。深蓝底色代表安静可靠，香槟金点缀代表温度和记忆。

一个数字助手的形象，最难的不是好看，是让人信任。

标签: #品牌设计 #AI助手 #视觉设计 #Anna #设计思考
```
