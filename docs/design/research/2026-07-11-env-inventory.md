# Environment variable inventory (env-config unification)

Tracking issue: #701.

This ledger enumerates every `os.Getenv` / `os.LookupEnv` read in non-test Go
code and records, for each, the semantics that block a purely mechanical `env`
struct-tag migration and the **final verdict**: either **migrated** onto
`config.ServerConfig` (parsed once at the server startup boundary and threaded
in) or **stays-custom** (read directly, for the stated reason). The scope
shipped as one change on `feat/env-config`.

A machine-checked guard backs this ledger: `TestNoUnapprovedEnvReads`
(`internal/config/env_scan_test.go`) walks every non-test compiled `.go` file
and fails on any `os.Getenv`/`os.LookupEnv` read whose `(file, variable)` pair is
not in its allowlist. Every **stays-custom** row below corresponds to an
allowlist entry; adding a new ambient env read fails the test until it is either
migrated or added here with a justification.

Read time:

- **boot** — read once during server startup / composition (`serverAction`,
  `setup`, `runServer`, `*.Init`).
- **setup** — read once inside a subsystem's constructor at startup.
- **per-call** — read on each invocation of a runtime function.
- **build** — read by a code generator, not the running server.

Empty-value semantics is what the current code does when the variable is set to
`""` (as distinct from unset).

## Normalization policy

Only the three typed fields whose legacy parsers already trimmed their input
(`STELLA_REQUIRE_EXTERNAL_DB`, `STELLA_HTTP_SHUTDOWN_TIMEOUT`,
`STELLA_RIVER_SOFT_STOP_TIMEOUT`) are **normalized**: `TrimSpace`, and a
whitespace-only or empty value is treated as **unset** so the default applies —
preserving the legacy `strings.TrimSpace(os.Getenv(...)) == "" → default`
behavior. `STELLA_DATABASE_URL` and `STELLA_SERVER_URL` are **not** normalized:
their legacy readers returned values untrimmed (a padded DSN must reach the
database layer, which is where it gets rejected; a whitespace-only
`STELLA_SERVER_URL` counted as set), so both are raw passthrough fields, with
the ServerURL default applied only to unset/exactly-empty.

Every variable migrated afterward is carried as a **raw passthrough field** read
with exact `os.Getenv` semantics (value or `""` for unset/empty; no trim, no
default). This is deliberate: their group-level validation and dialects
(`Blob` group constraint + `USE_SSL` dialect, `OIDC` `Validate` + scope split,
`Reflect` warn-and-clamp / enum, the `Vault` required-at-startup check) stay with
the consuming subsystem, so a raw field preserves behavior exactly while a
typed/normalized field would not. Secrets (`Vault.Key`, `OIDC.ClientSecret`) are
only stored and never logged.
