# Environment variable inventory (env-config unification)

Tracking issue: #701. Companion to the plan review (`sol-env-review`).

This ledger enumerates every `os.Getenv` / `os.LookupEnv` read in non-test Go
code (`rg 'os\.(Getenv|LookupEnv)'`) and records the semantics that a mechanical
`env` struct-tag migration would silently change. It is the gate for the
two-PR split: **PR1** lands the config model + startup boundary and migrates
only the boot-time-static reads that already live in `internal/config`; **PR2**
migrates the consumer packages, each with its own semantics test.

Read time:

- **boot** — read once during server startup / composition (`serverAction`,
  `setup`, `runServer`, `*.Init`).
- **setup** — read once inside a subsystem's constructor at startup.
- **per-call** — read on each invocation of a runtime function.
- **build** — read by a code generator, not the running server.

Empty-value semantics is what the current code does when the variable is set to
`""` (as distinct from unset).

## PR1 scope, confirmed

Five variables migrate now — the intersection of "read lives in
`internal/config` today" and "boot-time static":

`STELLA_REQUIRE_EXTERNAL_DB`, `STELLA_HTTP_SHUTDOWN_TIMEOUT`,
`STELLA_RIVER_SOFT_STOP_TIMEOUT`, `STELLA_DATABASE_URL`, `STELLA_SERVER_URL`.

The two other `internal/config` reads stay put with a note:

- `STELLA_HOME` — excluded by #701 (bootstrap, cached, normalized).
- `STELLA_SANDBOX_BACKEND` (`SandboxBackendEnvOverride`) — lenient allow-list
  read at backend-selection time, not a boot-static value. Migrating it would
  change its silent-fallback behavior, so it stays until PR2 decides
  deliberately.

## Normalization policy (PR1)

All five PR1 fields share one rule: `TrimSpace`; a whitespace-only or empty value
is treated as **unset** so the default applies. This preserves the current
`strings.TrimSpace(os.Getenv(...)) == "" → default` behavior of the duration and
bool readers, and extends the same trimming to the two string fields (previously
untrimmed) per the uniform policy in #701. Fields that must distinguish unset
from explicit-empty (e.g. `EMAIL_CONFIG` in PR2) opt out of this normalization
per-field.
