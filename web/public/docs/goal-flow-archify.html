Goal 生命周期 · 规划门数据流

feat/goal-plan-gate — Goal / Plan / Task 三状态机如何在创建、评审、物化、激活门、回收中联动

规划门 · ActivateGoal 守卫

  • • planned → running 拒绝，除非四条全满足：
  • • ① plan 存在 ② accepted_at 已盖 ③ materialized_at 已盖 ④ ≥1 个 required 子任务
  • • Errs: GoalPlanRequired / AcceptedPlanRequired / PlanNotMaterialized
  • • 不变式：running 的 goal 绝不会无计划、无物化、无子任务

Plan FSM · 评审与物化

  • • 编辑暂存在 pending_content_json（plan: draft）
  • • review_policy=human → in_review；approve 盖 accepted_at
  • • request-changes 保留 edit；reject 丢弃 edit，均回 planning
  • • Materialize 单事务、按 (source_plan_id, plan_item_id) 幂等
  • • replan 重物化：in-flight 子任务不动，移除项 detach/cancel

direct vs deferred

  • • direct（默认）：自动接受单项 plan + 物化 + 激活，一次事务直达 running
  • • deferred：仅落 draft goal，后续手动 CreateGoalPlan → accept → materialize → activate
  • • agent 只能建 goal，不能手写 goal 子任务（硬 gate）

Rollup 决策表 · goal_rollup.go

  • • 每个子 Task 转终态后触发 RollupGoal 重算
  • • 全部 required done → done；任一 failed/cancelled → failed
  • • 任一 blocked → blocked；blocker 解除回 running
  • • CancelGoal 级联取消所有非终态子 Task
