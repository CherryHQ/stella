---
title: 创建专业 Agent
---

专业 Agent 应该由拥有这个工作流的人或团队创建。

财务应该创建财务 Agent。HR 应该创建 HR Agent。工程应该创建工程 Agent。重点不是让所有人都变成自动化搭建者，而是让业务负责人一次性编码自己的工作方式，然后把 Agent 分享给所有需要它的人。

## 需要配置什么

### Instructions

Instructions 定义 Agent 的职责、语气、边界、升级规则和决策策略。

好的 instructions 会回答：

- 这个 Agent 负责什么工作？
- 行动前应该询问哪些问题？
- 必须遵守哪些规则？
- 哪些决策可以自己做？
- 哪些决策必须 review？

### Knowledge

Knowledge 给 Agent 专业上下文：

- 制度。
- 流程文档。
- 示例。
- Checklists。
- 产品文档。
- 内部参考资料。

Knowledge 应该由业务负责人维护，而不是让模型猜。

### Skills

Skills 教 Agent 可复用的方法：

- 筛选候选人。
- 检查报销材料。
- 准备发布 checklist。
- 总结政策变化。
- 起草 review brief。

当同一个工作流需要稳定执行时，就应该使用 skills。

### Tools

Tools 让 Agent 能真正行动：

- 读取文件。
- 搜索来源。
- 调用 API。
- 发送通知。
- 使用 OAuth 连接服务。
- 创建 task 来追踪工作。

不要因为工具存在就添加工具。只添加 Agent 完成职责真正需要的工具。

### 记忆策略

决定 Agent 应该记住什么：

- 每个用户的偏好。
- 过去的决策。
- 团队专属术语。
- 沟通风格。
- 多个 Agent 可共享的用户记忆。

记忆应该让工作更顺畅，但不能把上下文泄漏到错误边界。

## 共享 Agent

配置完成后，把 Agent 开放给正确用户和渠道。共享 Agent 应该像一个专业同事：对所有人保持同一个专业身份，同时对每个用户有个性化理解。
