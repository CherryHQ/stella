## Stella 记住了什么

Stella 会记住你告诉她的一切——跨会话、跨天、跨周。当你提到你的名字、时区、偏好的编码风格，或者你讨厌不必要的抽象时，Stella 会记录下来，并在下次聊天时回忆起来。

记忆按用户和代理隔离，所以你创建的每个代理都有自己对你的理解，知道你是谁、关心什么。

Memory 保存：

- **你的档案** — 名字、偏好、习惯、工作方式，以及你分享的其他任何个人信息。
- **约束条件** — 你设定的 Stella 必须始终遵守的规则，比如"删除文件前必须先问我"。
- **知识** — Agent 可以在需要时检索的持久事实。

Session 保存对话历史。活跃 Session 中的消息在压缩后仍然可以搜索。归档对话仍会保留，可通过 Session 管理显式查看，但不再进入 `memory.search`。

## 对话如何保持可控

随着对话越来越长，Stella 会自动将较旧的消息压缩为摘要。你不需要做任何事情——当对话变大时，这会在后台自动发生。

关键是：**不会丢失任何内容。** 摘要保留了重要细节，如果需要具体信息，Stella 可以深入查看。你可以在同一个会话中聊上好几周，Stella 仍然能回忆起第一天讨论的内容。

如果你开始新会话，Stella 会自动带上你的档案和约束条件。归档对话仍可通过 Session 管理显式查看，但不会再被自动召回。

## 开始新会话

有时你要的不是更短的对话，而是干净的对话。两个命令的区别是：

- **`/new`** 开始一个新会话。此前的会话被归档而不是删除——它不再进入 `memory.search`，但仍可通过 Session 管理显式查看；你的档案和约束条件也会自动带过去。
- **`/compact`** 留在当前会话里压缩历史，让上下文变短而不丢失思路。

`/new` 只在私聊中生效。群聊的上下文由所有成员共享，因此任何单个成员的命令都不能替其他人清空它——在群里输入 `/new` 会收到相应说明，且不会重置任何内容。群聊同样不支持 `/compact`。

在 Web UI 里请从侧边栏新建会话，而不是用命令：已经打开的聊天窗口会一直停留在它打开时的那个会话上。

## 管理你的档案

Stella 通过对话自然地了解你。如果你说"我在太平洋时区"或"我更喜欢 TypeScript 而不是 JavaScript"，她会记住。

你也可以直接让 Stella 管理你的档案：

- **"你知道我哪些信息？"** — Stella 会读出你存储的档案记录。
- **"更新我的档案：我已经改用 Neovim 了。"** — Stella 更新你的档案。
- **"忘掉我偏好暗色模式这件事。"** — Stella 删除该细节。

档案变更有版本记录。如果 Stella 更新了你的档案而你不满意，可以让她回滚：

- **"显示我的档案历史。"**
- **"把我的档案回滚到上一个版本。"**

## 设置约束条件

约束条件是 Stella 在每个会话中都遵守的持久规则。它们比偏好更强——是 Stella 在执行操作前会检查的硬性规则。

要添加约束条件，告诉 Stella 你想要什么：

- **"执行破坏性命令前必须先问我。"**
- **"永远不要直接提交到 main 分支。"**
- **"午夜到早上7点之间不要发送通知。"**

Stella 会在保存约束条件前跟你确认。一旦设定，它会应用于该代理的所有未来对话。

管理现有的约束条件：

- **"列出我的约束条件。"** — 查看所有生效的规则。
- **"删除关于通知的约束条件。"** — 删除特定规则。

## 搜索过去的对话

你可以随时搜索你的对话历史：

- **"搜索我们关于数据库迁移的讨论。"**
- **"上周二我们聊了什么？"**
- **"找到我提到部署脚本的地方。"**

Stella 会搜索活跃 Session 的对话记录并返回匹配的 Session 卡片，然后查看或翻页读取选中的对话记录。归档对话仍可通过 Session 管理显式打开，但不会出现在搜索结果中。对话检索归 Session 管理，Memory 则保存持久的档案、约束和知识事实。

如果一条消息由另一个 Session 中的 Agent 发出，对话记录会显示其来源。Stella 把它视为该 Agent 提供的信息，而不是你发出的指令。

## 小贴士

- **明确说出重要的事情。** 如果你希望 Stella 长期记住某件事，直接说："记住我的生产服务器在 10.0.1.5。"
- **用约束条件设定安全规则。** 约束条件比档案偏好执行得更严格。
- **切换话题时开始新会话。** 每个会话有自己的对话历史。重新开始能保持专注，而你的档案和约束条件会自动继承。
- **需要活跃上下文时使用搜索。** 与其维持一个无限长的会话，不如用搜索从活跃对话中提取相关历史；需要归档内容时则显式打开对应 Session。
