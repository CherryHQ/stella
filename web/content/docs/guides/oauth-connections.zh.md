---
title: OAuth 连接
---

Stella OAuth 连接会向显式声明 `oauth_provider` 的工具提供用户 token。内置 `gh` 使用这条链路；manifest 工具也可以声明其他已配置的 provider。

## OAuth 连接的作用

连接服务后，Stella 会安全保存访问令牌，并只注入声明了该 provider 的已启用工具。这意味着 Stella 可以：

- 使用 `gh` 创建 GitHub issue、开 pull request、查询仓库
- 通过 `lark-cli` 使用飞书/Lark 文档、日历、任务和消息
- 为显式声明 OAuth provider 的自定义 manifest 工具授权

provider 的 scope 设置和 token 刷新只影响这些消费者。

## 连接 GitHub

GitHub 开箱即用——不需要管理员设置。

### 方式一：在聊天中让 Stella 操作

1. 告诉 Stella："连接我的 GitHub 账号。"
2. Stella 会启动设备授权流程，给你一个 URL 和一次性验证码。
3. 在浏览器中打开 URL，输入验证码并授权。
4. Stella 检测到授权后确认连接成功。

### 方式二：使用Web UI

1. 打开Web UI，进入**凭据**页面。
2. 找到 **OAuth CLI Credentials**，点击 GitHub 旁边的**连接**。
3. Stella 会显示一个 URL 和一次性验证码。
4. 在浏览器中打开 URL，输入验证码并授权。
5. 授权完成后，状态会更新为已连接。

你可以随时在凭据页面点击**断开**来取消连接。

## 连接飞书或 Lark

管理员先在 **管理控制台 → 部署资源 → 系统凭据** 中配置飞书或 Lark OAuth 应用。之后，用户可以在聊天或个人**凭据**页面中通过与 GitHub 相同的浏览器授权流程完成连接。不要把 App Secret 粘贴到聊天中，也不要在 Agent 沙箱里运行 `lark-cli config init`。

内置 `lark-cli` 工具默认绑定飞书 provider；Lark 部署可以通过 tool manifest override 改为 `lark` provider。

## 管理员：管理 provider

管理员在 **管理控制台 → 部署资源 → 系统凭据** 中管理 OAuth provider。个人设置只包含当前用户自己的连接和密钥库条目。

### 应用凭据

设置 provider 的 **Client ID** 和 **Client Secret**。保存新凭据后，已连接的用户会被标记为需要重新连接，因为旧应用签发的令牌不再匹配。

### 权限范围（Scopes）

**最小权限**是每次连接都会请求的权限。它是下限而不是上限：用户的工具需要更多权限时，可以自行申请并重新授权，Stella 只会把这些权限合并进该用户自己的 desired scopes。用户实际能授予什么，由 OAuth 应用配置和 provider 的授权页面决定——Stella 不会在它们前面再加一道闸门。

管理员用权限编辑器覆盖这个下限：

- 清单始终显示所有内置权限。没有覆盖配置时默认全部勾选；保存后则按已保存状态勾选。取消勾选后，下次授权将不再请求该权限。
- 权限范围按命名空间前缀分组、默认收起，并支持搜索。
- **恢复默认**会选中全部内置权限，并从草稿中移除自定义权限。
- 使用清单下方的输入框添加内置列表中没有的权限。粘贴内容会按换行、逗号或空格拆分并自动去重。

保存后，勾选的权限成为所有用户的下限。修改下限**不会**静默扩大已签发令牌，但受影响的用户需要重新连接。降低下限也不会收回用户此前已申请的权限；他们的 desired scopes 只在重新授权时才会缩小。要真正移除已授予的权限，请断开连接并在 provider 侧撤销授权。

内置默认值按 provider 选定。Lark 和飞书默认包含 lark-cli 的完整能力范围，用户授权一次即可使用所有文档中的命令；GitHub 和 X 只包含其工具所需的权限。如果你的部署不需要这么多，请裁剪这个下限——首次授权页面越短，用户越容易接受；只有少数人需要的权限可以由他们自己增量申请。

下限中的每个权限都必须同时在 provider 的开发者后台开通。应用未开通的权限不会出现在授权结果里，表现为**需要重新连接**且重新连接也无法消除；此时应把它从下限中移除，或在开发者后台开通。

### 重新连接语义

一个连接可能显示为**已连接**但仍需要操作。出现下列情况之一时，provider 会显示**需要重新连接**状态：

- 用户连接之后应用凭据被轮换过，或
- 请求的权限范围现在包含存储令牌未持有的项（面板会列出具体缺失的权限范围）。

用户在同一面板中重新连接；令牌健康信息区块显示访问令牌与刷新令牌的过期时间，方便判断何时需要刷新。

## 使用已连接的服务

连接后，声明该 OAuth provider 的工具会在 Agent 会话中获得凭据。例如：

- "列出我仓库中的 open issue"
- "用这些更改创建一个 pull request"

Stella 会在后台自动处理认证。

## 故障排除

### 授权被重启中断

如果 Stella 在 provider 授权期间重启，请重新发起该连接。

### GitHub 命令不工作

在Web UI的凭据页面确认你的 GitHub 账号已连接。如果状态显示未连接，重新连接即可。GitHub 令牌不会过期，所以一旦连接就可以一直使用。
