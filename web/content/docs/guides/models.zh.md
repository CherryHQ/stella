title: 模型
---

Stella 支持多个 AI 提供商，让你选择哪个模型来驱动对话。你可以随时切换模型，无需重启。

## 支持的提供商

Stella 支持三种类型的提供商：

- **Anthropic** -- Claude 系列模型（Sonnet、Opus、Haiku）
- **OpenAI** -- GPT 和 o 系列模型
- **OpenAI 兼容** -- 任何实现了 OpenAI API 的服务，如 Perplexity、Together.ai 或本地模型服务

你可以同时配置多个提供商，在不同的代理中混合使用来自不同提供商的模型。

## 设置提供商

1. 打开Web UI。
2. 进入**提供商**部分。
3. 点击**添加提供商**并选择提供商类型。
4. 输入你的 API key 和所需设置（例如 OpenAI 兼容提供商的自定义 base URL）。
5. 保存提供商。

保存后，Stella 会自动从该提供商获取可用模型列表。

## 模型层级

Stella 中的每个代理最多使用三个模型层级：

| 层级     | Stella 何时使用                |
| -------- | ------------------------------ |
| **默认** | 日常对话和一般任务             |
| **强力** | 难题、复杂推理、多步骤分析     |
| **快速** | 快速检查、简单查询、轻量子任务 |

如果你只设置了默认模型，Stella 会将其用于所有场景。强力和快速层级是可选的——当你希望 Stella 自动为任务选择合适的模型时再设置。

## 部署默认值与按智能体覆盖

模型配置分为两层。

管理员在 **管理 -> 默认模型** 设置整个部署的默认值，就在支撑它们的提供商旁边：三档智能体模型及其思考等级，外加两个辅助角色（视觉与嵌入）。

每个智能体只需在自己的设置页覆盖需要改的部分。留空的字段继承部署默认值，因此新建的智能体开箱即用，而修改默认值会影响所有未覆盖该字段的智能体。

视觉和嵌入没有按智能体的配置项：读图和生成向量属于基础设施而非人格设定，因此整个部署共用一份。

## 视觉模型

管理员在 **管理 -> 默认模型** 为整个部署选择视觉模型。它为图片生成文字描述和转写，不会直接回复你。

### 一对一会话中的图片

在普通一对一会话中发送图片时，Stella 会在图片到达时生成一份不可变的文字基线。即使之后切换模型，后续对话也使用同一份基线。

在引入图片的当前回合内——包括该回合里的所有工具循环：

- **Input** 声明了 `image` 的模型会收到图片像素。
- 纯文本模型或未声明的模型会立刻收到文字基线。

之后的回合里，所有模型都会收到同一份基线文字，而不是原始像素。如果 Stella 无法生成基线，会稳定地使用标记 `[Image baseline unavailable.]`，不会重试或编造描述。

原始图片仍可在你有权限访问的 Web 对话历史中查看。

### 使用 `view_image` 检查已有图片

Agent 可以调用 `view_image(path, prompt?)` 检查沙箱内的图片文件。该工具接受 PNG、JPEG、GIF 和 WebP。相对路径使用 Agent 当前的工作目录；`$HOME`、`$STELLA_ASSETS_DIR` 和 `$TMPDIR` 表示 Agent 能看到的沙箱根目录。Stella 通过沙箱读取文件，不会暴露文件在宿主机上的物理路径。

Stella 根据当前回合实际使用的模型选择结果：

| 当前模型与视觉设置                                   | 结果                                                                   |
| ---------------------------------------------------- | ---------------------------------------------------------------------- |
| 当前模型声明支持 `image` 输入                        | 模型收到验证后的图片像素。可选的 `prompt` 不会触发单独的视觉模型调用。 |
| 当前模型未声明支持 `image`，并且配置了可用的视觉模型 | 视觉模型接收图片并返回文字证据。`prompt` 用于指定需要重点检查的内容。  |
| 没有可用的视觉模型，并且未提供 `prompt`              | 如果能够生成，Stella 返回通用的文字转写和场景基线。                    |
| 没有可用的视觉模型，并且提供了 `prompt`              | 工具返回可行动的错误，因为通用基线无法诚实地回答定向视觉问题。         |

“当前模型”指这一回合最终实际选择的模型，包括模型调用前发生的切换。未声明图片能力的模型按纯文本模型处理，Stella 不会冒险向它发送像素。

当提供商没有返回输入能力元数据时，在 **管理 -> 默认模型** 中选择一个视觉模型，即表示管理员声明该模型可以检查图片。如果该模型明确声明只支持文本输入，Stella 会把它视为不可用，并且绝不会向它发送图片字节。视觉提供商调用失败或通用基线生成失败时，工具会返回错误，不会伪装成检查成功。

图片中产生的文字会被包装为不可信证据。Agent 可以引用和分析这些文字，但不会把图片里的文字当作指令执行。

`view_image` 会在选择任何路由前验证文件的真实内容。文件扩展名不决定格式，Stella 根据实际字节识别图片；内容损坏、不支持或不安全的图片会被拒绝。PDF、DOCX、XLSX、PPTX 等文档应使用 `bash` 配合 `xberg extract`。`view_image` 不生成或编辑图片。

若要让多模态模型在当前回合收到图片像素，请打开 **管理 -> 提供商**，编辑该模型，把 **Input** 设为 `text, image`。这个声明同时控制当前回合的原生图片输入和 `view_image` 的像素路径，不会改变较早会话图片的呈现方式。
