---
title: 密钥管理
---

## 保险库的作用

Stella 的保险库安全存储你的 API 密钥、令牌和其他机密信息。数据在存储时加密，并在代理会话中自动作为环境变量使用。你无需在聊天中粘贴密钥或在脚本中硬编码——存储一次，Stella 在需要时自动使用。

## 设置

使用保险库前，你需要生成一个主加密密钥并提供给 Stella。

### 1. 生成主密钥

```bash
age-keygen
```

这会打印一个公钥和一个私钥。复制以 `AGE-SECRET-KEY-1` 开头的那一行。

### 2. 使用密钥启动 Stella

```bash
export STELLA_VAULT_KEY="AGE-SECRET-KEY-1..."
stella server
```

> **请备份你的主密钥。** 如果丢失，所有存储的机密信息将永久无法恢复。请将其保存在密码管理器或其他安全位置。

这就是全部设置。当新用户加入时，Stella 会自动处理每个用户的加密。

## 添加机密信息

### 从管理面板

1. 打开管理面板，进入凭据页面。
2. 在保险库部分，输入密钥名称（例如 `GITHUB_TOKEN`）和对应的值。
3. 点击保存。

密钥值为只写模式——保存后，明文不会再在管理面板中显示。你可以看到密钥名称列表，但看不到它们的值。

### 从聊天会话

你也可以在对话中直接存储机密信息。当 Stella 需要一个她没有的密钥时，她会要求你提供。使用 config 命令发送：

```
/config SECRET_NAME your-secret-value
```

这会直接将值写入你的保险库，不会暴露在对话历史中。密钥存储后，Stella 会自动继续你的任务。

你还可以让 Stella 管理你的机密信息：

- **"列出我的保险库密钥。"**
- **"删除 GITHUB_TOKEN 密钥。"**

## 在会话中使用机密信息

当代理会话启动时，你所有的保险库机密信息会被解密并注入为环境变量。名为 `GITHUB_TOKEN` 的密钥在会话中可以通过 `$GITHUB_TOKEN` 访问。

每次会话都会重新加载机密信息。如果你添加或更新了密钥，更改会在下次会话时生效。

### 自动生成的令牌

Stella 会自动为每个用户创建一个 `STELLA_TOKEN`。这个令牌用于在代理会话中验证 CLI 命令和 API 请求。你不需要手动创建它。

## 密钥命名规则

密钥名称必须遵循以下规则：

- 仅限大写字母、数字和下划线（例如 `MY_API_KEY`）
- 必须以字母开头
- 最长128个字符
- 不能以保留前缀开头，如 `STELLA_`（自动生成的 `STELLA_TOKEN` 除外）

## 小贴士

- **每个服务一个密钥。** 将 `GITHUB_TOKEN`、`OPENAI_API_KEY` 等类似密钥作为单独的保险库条目存储。
- **密钥在重启后持续存在。** 你只需要设置一次。
- **使用管理面板进行审计。** 凭据页面显示所有密钥名称，方便你查看已存储的内容而不暴露值。
- **通过覆盖来轮换密钥。** 要更新密钥，用相同的名称保存新值——它会替换旧值。
