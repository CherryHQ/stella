---
title: 交付物概览
---

交付物用于需要被追踪、迭代执行的成果，而不是只需一条聊天回答的请求。

**交付物**是 Agent 推动至验收的一个成果。它带着意图（「完成」意味着什么）、验收契约（系统如何检查产物）以及每一次尝试的记录。交付物是递归的：

- **根**交付物是你的目标。
- **子**交付物是它拆解出来的 sub-deliverable。
- 每个交付物要么是**叶子**（leaf，由 worker 直接执行），要么是**复合**（composite，先规划成子项）。

## 完成是推导的，不是声明的

Agent 从不把交付物标记为「完成」。它提交**证据**（evidence，也就是它产出的工作），由系统按交付物的**验收契约**检查这些证据：

- **检查**（check）自动运行（命令正常退出、文件存在、测试通过），系统读取结果。
- **评判**（judgment）让 Agent 或人按 rubric 做出决定并记录裁决。

如果契约通过，交付物变为**已验收**，其产物被冻结，供依赖它的工作使用。如果不通过，差距会作为下一次尝试的输入。这正是你要在一开始就写清完成标准的原因——它就是工作被衡量的尺子。

## 收敛循环

叶子交付物以有界的返工循环运行，而不是一次性执行：

1. 依赖满足 → 交付物变为**进行中**。
2. Agent 在它的 session 里工作并提交证据。
3. 系统按验收契约评估。
4. 通过 → **已验收**。未通过 → 差距成为下一次尝试的输入——这就是返工。
5. 尝试次数用尽 → **已阻塞**，你可以提高预算或放弃它。

每次尝试都会保留，所以记录读起来很清晰：第 1 次尝试产出 X，验收发现差距 Y，第 2 次尝试产出 Z，验收通过。

## 生命周期状态

交付物会经过：

- **草稿** — 已创建，尚未激活。
- **就绪** — 在依赖和调度满足后可运行。
- **进行中** — Agent 正在处理。
- **已阻塞** — 因等待你的裁决、依赖失败或尝试预算用尽而暂停。
- **待验收** — 已提交证据，等待评判裁决。
- **已验收** — 验收契约通过。（推导得出，终态。）
- **已否决** — 关闭且无返工路径。
- **已放弃** — 你彻底放弃了它。
- **已取消** — 你停止了它。

## 拆解

复合交付物不能直接运行——必须先规划成子项。Agent 编写一份拆解（也就是 plan：子交付物以及它们之间的依赖）；根据审核策略，它会被自动接受或等待你批准。一旦接受，子项被生成，每个子项各自运行收敛循环。

当所有必需子项都已验收，父交付物会运行**自己的**验收评估——和每个交付物一样的关卡，只是作用在根上。没有单独的「最终综合」步骤；它从递归中自然得出。

## 依赖关系

依赖关系让执行顺序可见，并把**已验收产物**向下游传递——只有当上游兄弟项被验收后，子项才能看到它的产物。

适合添加依赖的场景：

- 一个交付物需要另一个的已验收产物。
- 上游失败时，下游交付物应该停止。
- 你希望就绪视图准确解释还有什么在等待。

硬依赖失败会阻塞下游交付物，直到你带理由豁免它。

## 审核与评判

有些成果应该停下来等待人类决定。把它们交给一个 `human` 权限的**评判**项，用于：

- 制度例外。
- 候选人推荐。
- 发布审批。
- 面向客户的回复。
- 任何会改变金钱、权限或声誉的事情。

评判裁决同样以**证据**形式记录——一条带理由、范围和权限的批准——而不是手动翻转状态。系统据此推导验收结果。

## 交付物界面

聊天记录不是好的项目管理工具。在 Web UI 中，打开某个 Agent 后进入**交付物**页签，就能在同一处查看根交付物、定时工作及其子项。Project 页面也会先打开它的交付物列表。

打开一个交付物可查看：

- 它当前的生命周期状态和就绪情况。
- **子项**及其汇总状态（针对复合交付物）。
- **尝试** — 每次执行过程，以及驱动下一次尝试的差距。
- **验收**记录 — 每条检查结果和评判裁决。
- **依赖** — 以及还有什么在等待。
- 已验收产物，以及任意一次尝试背后的 session。

当交付物因等待你而阻塞时，它的页面会显示需要什么——直接在那里提交裁决，或豁免一个失败的依赖。Agent 会带着你的输入继续这项工作。

实用规则：用聊天描述成果和决策；用交付物追踪执行。
