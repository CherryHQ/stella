---
title: 任务系统概览
---

Stella 的任务系统用于处理无法通过单条聊天回答完成的 goal。

当你给 Agent 一个 goal，Stella 可以把它变成工作流：规划工作、拆分 task、连接依赖、定义验收标准、追踪 blocker、记录事件、运行 Agent，并把结果送入 review。

## Goal 到 plan

用户给 Agent 一个结果目标：

> 准备 Q2 报销审计包，并标出需要财务 review 的问题。

Agent 不应该只回答建议。它应该识别为了达成结果需要完成哪些工作。

## Plan 到任务 DAG

Stella 可以把 plan 表达为带依赖的 tasks：

- 收集报销记录。
- 提取票据信息。
- 根据制度检查每条报销。
- 标记例外。
- 准备 review packet。
- 请财务 review 例外项。

依赖很重要。制度检查没完成前，review packet 不应该被标记为 ready。DAG 让这种结构可见。

## 验收标准

每个 task 都应该有清楚的完成定义。验收标准让 Agent 的工作可以被 review：

- 所有必需票据字段已提取。
- 每条报销被标为通过、警告或需要 review。
- 每个警告都引用触发它的制度规则。
- 最终 packet 包含摘要和附件。

## Review 和审批

有些工作应该停下来等待人类判断。Stella 的任务系统让 Agent 把结果送入 review，而不是假装自己有审批权。

适合 review 的场景：

- 制度例外。
- 候选人筛选建议。
- 发布审批。
- 面向客户的回复。
- 任何会改变金钱、权限或声誉的事情。

## 任务 UI

任务 UI 存在的原因很简单：聊天记录不是项目管理工具。用它查看：

- 当前 task 状态。
- 依赖关系。
- Blockers。
- 验收标准。
- 事件和运行记录。
- Review 状态。

实用规则：用聊天交付 goal 和上下文；用任务 UI 查看执行过程。
