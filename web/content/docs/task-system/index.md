---
title: Deliverables
---

A **deliverable** is one outcome you ask an agent to drive to acceptance — not a single chat reply, but tracked work that outlives one message.

Use deliverables when an outcome needs multiple attempts, dependencies, blockers, a clear bar for "done," or human sign-off. You describe the outcome and how acceptance should look; the agent works toward it, the system checks the work against an acceptance contract, and it reworks until the contract passes. Completion is **derived** from that contract — never a box the agent ticks.

A deliverable is recursive: a **root** deliverable is your objective, and the agent can decompose it into **child** deliverables (sub-deliverables) that each converge on their own.
