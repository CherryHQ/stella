---
title: 将目标复用为定时工作流
---

当你想让同一份计划重复运行、又不想让规划器每次重新拆解时，可以把已验收的复合目标保存为工作流。

## 开始前

你需要一个已验收的复合目标。从目标保存出的工作流会冻结已验收的拆解计划，而不是复用上一次运行的结果。

具体 CLI 语法以 `stella workflow --help` 为准。

## 保存已验收目标

你可以直接让 Stella 保存目标，也可以用 workflow CLI 按目标 ID 保存。名称尽量短，说明这个可重复任务做什么。

工作流有版本。以后编辑工作流会创建新版本；已存在的定时任务仍然引用创建时指定的那个精确版本。

## 为变化内容添加输入

输入是类似 `{{inputs.customer}}` 或 `{{inputs.date_range}}` 的命名占位符。它们可以替换到标题、意图、判断提示词和评分标准中。

Stella 不会把输入替换到可执行检查命令里。必填输入缺失时，运行会在创建新目标树之前失败。

输入名称和引用在保存时校验：名称只能包含字母、数字、`_` 和 `-`，计划中引用的每个 `{{inputs.name}}` 都必须是已声明的输入。

## 手动运行

先看 `stella workflow run --help`，再带上需要的输入运行工作流。每次运行都会创建一个新的根目标；原来已验收的目标保持关闭。

## 每天定时运行

先看 `stella scheduler add --help`，再用 `--workflow <workflow-id>` 和 cron 表达式创建定时任务。比如你可以对 Stella 说：“把这个目标保存成工作流，每天早上运行。”Stella 应先保存目标，再创建工作流定时任务。在 Web UI 中，工作流详情页的 Schedule 按钮可以完成同样的事。

v1 的 cron 使用服务器本地时间。

## `fully_frozen` 是什么意思

`fully_frozen` 表示每个复合节点都有已保存的计划。定时工作流默认要求完全冻结，这样每次都会重放同一份结构，不会发生规划漂移。

部分冻结的工作流可以把某些子计划留给运行时重新规划。要定时运行这类工作流，必须显式允许 replan。

## 重叠运行行为

只有当上一次工作流运行已完成实例化、且它的根目标仍在活跃状态时，调度器才会跳过本次触发。实例化失败不会阻塞下一次 tick；卡住的实例化会被恢复，而不是复制一棵新树。
