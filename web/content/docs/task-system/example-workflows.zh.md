---
title: 示例工作流
---

这些例子展示如何把较大的诉求构建成目标。你描述根成果及其验收标准；Agent 把复合目标拆解成子项，推动每一项至验收，并按差距返工，直到契约通过。

## 财务报销 review

根目标：

> 审计这份客户晚餐报销材料；如有需要，准备财务 review。验收标准：每一条都经过制度检查、例外项已标出、材料包可交财务。

Agent 可能把它拆解成子项：

- 提取发票和参与人信息。
- 检查制度要求。
- 识别缺失字段。
- 标记制度例外。
- 起草报销材料包。
- 把例外项交给人工财务裁决。

有用的依赖：

- 制度检查消费已验收的票据提取结果。
- 例外 review 消费已验收的制度检查。
- 最终材料包消费提取结果和例外 review。

评判关卡：

- 制度例外需要人工财务裁决。
- 缺少税务或票据信息时，阻塞等待用户输入。
- 付款审批仍由财务人员负责。

## HR 招聘流程

根目标：

> 根据后端岗位筛选这些候选人，并准备 hiring panel review。验收标准：每位候选人都按 rubric 评分，panel packet 完整。

Agent 可能把它拆解成子项：

- 提取简历事实。
- 根据岗位 rubric 对比候选人。
- 总结证据。
- 识别缺失的面试信号。
- 准备 panel review packet。
- 把推荐交给人工 panel 裁决。

有用的依赖：

- Rubric 对比消费已验收的简历事实。
- 证据总结消费已验收的 rubric 对比。
- Panel packet 消费总结和缺失信号检查。

评判关卡：

- 候选人推荐需要人工裁决。
- 敏感或不完整证据会被标记。
- 最终录用决定不交给 Agent。

## 工程发布

根目标：

> 规划 billing workflow 发布，并追踪上线前所有 blocker。验收标准：实现与验证均通过，且上线已获批准。

Agent 可能把它拆解成子项：

- 阅读发布计划。
- 识别受影响服务。
- 实现改动。
- 验证改动。
- 追踪 blocker。
- 把上线批准交给人工裁决。

有用的依赖：

- 实现消费受影响服务分析。
- 验证消费已验收的实现——其检查（构建、测试）就是实现这个目标自己的验收契约，自动运行，失败则返工。
- 上线批准消费验证结果。

评判关卡：

- 高风险 migration 需要工程裁决。
- 面向客户的变化需要产品裁决。
- 上线批准仍由人负责。
