---
title: 给 Agent 一个目标
---

使用 Stella 应该像向一个靠谱同事求助。

你不需要知道 Agent 会使用哪个 tool、API、制度文档或工作流。把 goal、相关上下文和约束告诉它。Stella 会为 Agent 准备 memory、knowledge、skills、tools 和 workspace context。

## 写清楚结果

好的例子：

> 为这次客户晚餐准备报销材料。告诉我还缺什么；如果有例外项，请创建财务 review 工作。

弱的例子：

> 帮我处理费用。

Agent 可以追问，但清楚的结果会节省时间。

## 加上约束

有用的约束：

- 截止时间。
- 输出格式。
- 审批边界。
- 谁需要 review。
- 应使用哪些来源文档。
- Agent 不能做什么。

## 让 Agent 使用自己的上下文

共享 Agent 自带上下文：

- 业务负责人写的 instructions。
- 工作流相关 knowledge。
- 可复用方法 skills。
- 外部行动 tools。
- 关于你和你偏好的 memory。

所以你可以正常提出请求，而不是手动驱动每一步。

## 较大的目标会变成受追踪的 Goal

你交出去的目标不只是一条聊天回复——它会变成 Agent 推动至验收的受追踪**目标**。对于多步骤的目标，把它说清楚，并写明「完成」应该是什么样：

> 为这件事创建一个目标，把它拆解成步骤及其依赖关系，包含我们需要的人工签字节点，然后运行它。验收标准：材料包完整、例外项已获批准。

Agent 把复合目标拆解成子目标，并推动每一项至验收，按差距返工，直到验收契约通过。直接（单步）目标创建即运行；拆解型目标先规划、再激活。完成状态是从契约**推导**出来的——Agent 从不自己把它标记为完成。

用聊天提供上下文和决策；在 Agent 的**目标**页签查看执行状态。复合目标详情页会打开工作流画布：点击正在运行或阻塞的节点查看尝试、就绪状态和裁决表单；从页头打开**时间线**，在非上游依赖阻塞时留言授权额外一次重试。完整模型见[目标](/docs/task-system/overview)。
