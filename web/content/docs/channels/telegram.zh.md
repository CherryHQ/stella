---
title: Telegram 机器人
---

Stella 内置了一个通过长轮询连接的 Telegram 机器人 —— 无需 webhook 或公网 IP。你可以直接在 Telegram 中与 AI 助手对话、发送图片和文档进行分析，也可以在群聊中使用。

## 前提条件

开始之前，请确保你已具备：

- 一个正在运行的 Stella 服务器（`stellad server`）
- 至少在Web UI中配置了一个 AI 提供商（如 Anthropic、OpenAI）
- 一个 Telegram 账号

## 设置

1. 打开 Telegram，向 [@BotFather](https://t.me/BotFather) 发消息创建一个新机器人。保存它给你的 bot token。
2. 如果尚未启动，先启动 Stella 服务器：

   ```bash
   stellad server
   ```

3. 打开Web UI `http://localhost:25678`。
4. 进入 **Channels** 页面，添加一个新的 Telegram 频道实例。
5. 将你的 bot token 粘贴到配置中并保存。
6. 重启 `stellad server` 以激活新频道。

你可以创建多个 Telegram 频道实例（如果你有多个机器人）。每个实例可以在Web UI中绑定到专用的 agent。

所有频道配置（token、允许的 ID、专用 agent 绑定等）都通过Web UI管理。

## 多用户支持

每个 Telegram 用户会从其平台身份自动识别。会话按用户和 agent 分别管理，不同用户拥有各自独立的对话历史。无需手动设置用户。

## 流式响应

机器人实时流式传输 LLM 响应，采用两种策略：

### 私聊：Draft API（Bot API 9.3+）

使用 `sendMessageDraft` 实现流畅的动画流式传输，无需担心速率限制问题。如果 API 不可用，会自动回退到编辑模式。

### 群聊与话题：就地编辑

在群组、超级群组和论坛话题中，Stella 会发送一条进度消息，并在文本或工具状态变化时约每秒编辑一次。同一条消息会变成最终回复；超长回复会继续发送额外消息。处理期间 Stella 也会保持 Telegram 的「正在输入」提示。如果响应流失败，进度消息会显示安全的失败提示，而不会悄悄消失。

### 工具指示器

当助手执行工具时，你会在流式消息中看到状态指示器：

| 工具     | 指示器 |
| -------- | ------ |
| `bash`   | 闪电   |
| `read`   | 书本   |
| `write`  | 铅笔   |
| `edit`   | 扳手   |
| `search` | 放大镜 |

## Markdown 渲染

回复会转换为 Telegram MarkdownV2。若某条消息以 markdown 发送失败，Stella 会以纯文本重发，不会丢内容。

Telegram 没有折叠容器，因此 `<details>` 会被展开：`<summary>` 变成加粗标题，正文按普通 markdown 输出。`<https://example.com>` 形式的自动链接会被改写为行内链接，否则会被 MarkdownV2 转换器丢弃。

## 图片支持

你可以在私聊中向机器人发送照片。当你发送图片时：

1. 机器人从 Telegram 下载最高分辨率版本
2. 保存到你的私有 assets 目录，方便 agent 之后再次使用（裁剪、OCR、转发等）
3. 将其作为多模态消息（保存路径 + 图片 + 可选说明）发送给模型
4. 模型分析图片并用文本回复

使用场景：描述截图、分析图表、从照片中读取文档等。

如果模型返回图片（例如来自工具结果），它们会在文本响应后作为 Telegram 照片发送回来。

> **注意：** 在 **设置 -> 视觉** 配置普通会话的图片基线。**Input** 声明了 `image` 的模型只在当前回合收到像素；没有已存基线的群组历史使用不可用标记。

## 文件/文档支持

你可以向机器人发送文档（PDF、DOCX、XLSX 等文件类型）。当你发送文档时：

1. 机器人将文件保存到你的私有 assets 目录
2. 图片类文件会直接作为多模态输入传给模型；其他文件附带 xberg 提取提示，以便 agent 读取文件内容
3. 你附加的说明文字会作为你的文本消息一并传入

对于非图片文件，agent 随后可使用 `xberg extract` 命令解析文件。

> **注意：** 文件上传需要支持视觉/文档的模型，并且需要为活跃 agent 启用 Xberg skill。

## 群组支持

群聊默认关闭，需要在 Web UI 中打开**允许群聊**；关闭时所有群消息都会被拒绝。论坛话题与同一超级群组中的其他话题分别保存群组上下文和历史。

你可以选择设置**允许的聊天 ID**，把机器人限制到指定群组；也可以设置**允许的话题 ID**，进一步限制到指定论坛话题。话题条目使用 `chat_id:thread_id`（例如 `-1001234567890:42`）。两个列表为空时保留原有的宽松行为：只要启用群聊，机器人所在的每个群组都可以使用。任一列表配置后，不匹配的群组或话题会在到达 Agent 前被拒绝。

群消息默认必须 @机器人。命令也遵守同一规则：开启必须 @机器人时，在群里使用 `/help@your_bot`，或回复机器人消息。关闭**必须 @机器人**后可以使用 Stella 的语义群聊路由；同时还要在 BotFather 中关闭 bot privacy mode，让机器人能读取普通消息。

## 访问控制

**允许私信**控制私聊和账号关联。已关联的 Stella 用户继续使用自己的普通 session 和权限。

未关联的私聊发送者默认会被拒绝。只有在你希望他们通过持久、受限的访客 session 使用渠道绑定的 Agent 时，才启用**允许访客私信**。访客历史会持久保存和压缩，但没有 profile、reflection、工具、skills、文件、workspace、plugins 或 delegation。访客只能使用 `/link`、`/help`、`/new`、`/compact` 和 `/abort`；附件会在下载前被拒绝，关联账号也不会合并此前的访客历史。

系统会限制每位访客的消息速率和每个渠道的持久访客数量，并在配置的保留期后删除不活跃访客及其 session。公开访客访问仍可能产生模型费用和滥用风险。请使用专用且对访客安全的 Agent，并确保其 base prompt 不含 secret。

## 通知

机器人同时作为通知后端。你可以在Web UI中配置默认通知聊天和可选的广播频道。

用于：

- `notify` agent 工具（在服务器模式下）
- 调度器任务结果广播

## 命令

| 命令                | 描述                                     |
| ------------------- | ---------------------------------------- |
| `/start` 或 `/help` | 欢迎和帮助信息                           |
| `/new`              | 开始新会话（此前的历史退出记忆搜索）     |
| `/compact`          | 就地压缩当前会话（同一会话，上下文更短） |
| `/abort`            | 取消正在进行的响应                       |
| `/whoami`           | 显示你的用户 ID                          |

`/new` 仅在私聊中生效。群聊的上下文由所有成员共享，因此在群里输入 `/new` 只会回复共享会话无法重置，不会改变任何内容；该命令本身也不会进入群聊历史。新会话保留哪些内容，见[记忆](/docs/guides/memory)。

## 配置参考

以下所有设置都通过Web UI管理。

| 字段                             | 描述                                          | 默认值   |
| -------------------------------- | --------------------------------------------- | -------- |
| `token`                          | Bot API token                                 | （必需） |
| `channel_id`                     | 主动通知的默认目标（@name 或数字 ID）         |          |
| `allow_group`                    | 接受机器人所在群聊的消息                      | `false`  |
| `allowed_chat_ids`               | 可选：允许使用机器人的群组或超级群组 ID       | 空       |
| `allowed_topic_ids`              | 可选：允许使用的 `chat_id:thread_id` 论坛话题 | 空       |
| `allow_dm`                       | 接受私聊和账号关联                            | `true`   |
| `allow_unlinked_dm`              | 允许未关联私聊发送者使用受限访客 session      | `false`  |
| `guest_message_limit_per_minute` | 每位访客每分钟的消息和命令上限                | `10`     |
| `guest_max_per_channel`          | 此渠道可持久保存的访客身份上限                | `1000`   |
| `guest_retention_days`           | 超过此时间未活动时删除访客身份及 session      | `30`     |
| `require_mention`                | 在群聊中要求 @机器人                          | `true`   |

两个 allowlist 都为空时，`allow_group` 保持向后兼容：机器人所在的每个群组都可以触达绑定 Agent。当机器人也在不应访问的群组中时，请配置 allowlist。两个列表都配置时，消息必须同时匹配；话题列表不会因为另一个群组存在相同 thread ID 而放行。

## 故障排除

**机器人不响应消息？**

- 确保 `stellad server` 正在运行，且 Telegram 频道已在Web UI中配置。
- 仔细检查 bot token 是否正确。你可以向 [@BotFather](https://t.me/BotFather) 发消息查看你的机器人列表来确认。
- 如果在私聊中测试，请确认已启用**允许私信**。

**机器人在群组中不响应？**

- 最可靠的触发方式是 @提及机器人。
- 打开**允许群聊**。它默认关闭，会拒绝所有群消息。
- 如果你期望无 @提及也能回复，确认至少一个群内 agent 配置了可用于路由的模型，并且消息是明确请求而不是闲聊。
- 确保机器人已被添加到群组中，并有权限读取消息。Telegram 中如果要使用无 @提及路由，需要在 BotFather 里关闭 bot privacy mode。

**图片或文件未被分析？**

- 在 **设置 -> 视觉** 配置普通会话的图片基线。声明 `text, image` 的模型只在当前回合接收像素；没有已存基线的群组历史使用不可用标记。
- 文件上传需要为活跃 agent 启用 Xberg skill。
