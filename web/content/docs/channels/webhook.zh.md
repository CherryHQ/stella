---
title: Webhook
---

Webhook 频道把一个 Agent 变成一个 HTTP 端点，任何脚本、定时任务或第三方服务都能触发它。它是**仅入站**的：调用方 POST 一个负载，绑定的 Agent 运行，你要么得到一个即发即忘的确认，要么在 HTTP 响应里拿到 Agent 的回复。这里没有机器人、没有聊天窗口，Agent 也无法主动带外给你发消息——它为自动化而生，而非对话。

访问方式是一种**能力（capability）**：每个用户拥有自己的 Webhook 频道，并为自己的频道激活端点。Stella 一次性地披露一个包含不透明密钥的 URL。持有该 URL 就是全部凭证——没有单独的令牌或 `Authorization` 头，且该 URL 固定频道所有者的身份。

## 前提条件

开始前，请确保你已具备：

- 一个运行中的 Stella 服务（`stellad server`）
- 在 Web UI 中至少配置了一个 AI 提供方（如 Anthropic、OpenAI）
- 一个你希望该 Webhook 运行的已启用 Agent

## 工作原理

1. 用户在 Web UI 中创建自己的 Webhook 频道，并绑定一个自己可使用的 Agent。
2. 用户为该频道**激活能力端点**；它始终以频道所有者的身份运行，没有所有者选择器。
3. Stella 一次性披露 URL `https://your-host/webhooks/<capability>`，仅此一次。请当场复制；之后不再显示。
4. 调用方向该 URL 发送 `POST`。该 URL 即凭证——不使用 `Authorization` 头，任何发送的请求头都会被忽略。
5. 请求体成为 Agent 的消息。Agent 始终以**端点固定的所有者身份**运行，使用该所有者的工具、记忆与权限，并在每次触发时重新校验。
6. 根据回复模式，调用方要么立即得到 `202 Accepted`，要么等待 Agent 的回复。

所有者运行绑定 Agent 的权限会在每次请求时重新校验。若所有者失去访问权限（被移除分配、账号停用、Agent 或频道被禁用），后续触发会以不透明的 `404` 失败关闭——只要固定身份仍然有效，能力才继续可用。

## 设置

### 1. 创建 Webhook 频道

Webhook 频道是个人资源：每位已认证用户只能创建和管理自己的 Webhook。其他频道类型仍是管理员管理的部署资源。

1. 进入**频道**页面并新增一个频道。
2. 平台选择 **Webhook**，并给它一个频道 ID（例如 `deploy-notify`）。
3. 选择**绑定的 Agent**——每次触发时运行的 Agent。
4. 保存。每次调用方触发能力 URL 时选择回复和会话模式。

### 2. 激活能力端点

1. 打开该频道，找到**能力端点**面板。
2. 点击**激活端点**。它会以当前账户身份运行；该账户当前必须被允许运行绑定的 Agent。
3. 复制确认中显示的**一次性 URL**。它**仅显示一次**且无法找回；若丢失，请轮换端点以获取新的 URL。

频道所有者在创建时固定，不能更改。管理员也不能覆盖其他用户的个人 Webhook。

### 3. 触发它

```bash
curl -X POST https://your-host/webhooks/stella_whk_your_one_time_capability \
  -H "Content-Type: text/plain" \
  --data 'Deployment v1.4.2 finished. Summarize the changelog and post it to #releases.'
```

整个请求体作为消息传给 Agent。发送纯文本、JSON 或任何内容——Agent 原样接收并自行决定如何处理。无需也不会读取 `Authorization` 头：URL 本身就是密钥，请像对待密码一样对待它。

### 轮换或撤销

- **轮换**会签发一个新的一次性 URL，并立即使上一个失效。若 URL 可能泄露，或你没能复制到某个 URL，可用它恢复。
- **撤销**会删除端点；该端点的所有 URL 立即停止工作。频道仍保留，之后可再激活一个新端点。

## 回复模式

每次触发要么是异步（即发即忘），要么是同步（等待回复）。调用方通过 `?wait=true|false&session_mode=ephemeral|persistent` 按请求选择；缺省时安全地使用异步和临时会话。

| 模式 | 如何选择                   | 响应                                                      |
| ---- | -------------------------- | --------------------------------------------------------- |
| 异步 | 默认关闭，或 `?wait=false` | 立即 `202 Accepted`，携带 `{ "session_id": "..." }`       |
| 同步 | 默认开启，或 `?wait=true`  | `200 OK`，携带 `{ "session_id": "...", "output": "..." }` |

为单次调用强制同步：

```bash
curl -X POST 'https://your-host/webhooks/stella_whk_your_one_time_capability?wait=true' \
  --data 'What is 2 + 2?'
```

同步模式下，调用方最多等待频道的**等待超时**（默认 60 秒，每个频道可配置，最长 10 分钟）以获取回复。若超时时 Agent 仍在工作，你会得到 `504 Gateway Timeout`——但运行会在后台继续，且响应包含 `session_id`，你稍后可在 Web UI 中查看结果。

`?wait=` 若为 `true`/`false`（或 `1`/`0`）以外的任何值，将以 `400 Bad Request` 拒绝。

## 会话模式

- **临时（Ephemeral，默认）**：每次触发都开启一个全新会话，不记得之前的调用。适合无状态自动化——每个负载独立处理。
- **持久（Persistent）**：端点的所有者为该 Webhook 保留一个长期会话，使 Agent 跨调用积累上下文。适合后续触发需要在先前基础上继续的场景。

> **持久会话与并发：** 持久会话一次只运行一次触发。若某次触发到来时上一次运行仍在进行，它会被 `429 Too Many Requests` 拒绝（两种回复模式均如此）——请等待进行中的运行结束后重试。临时模式不受影响：每次触发都有自己的会话。

> **持久会话：** 持久模式为运行使用一个长期的 Agent 运行器。Stella 支持单个服务副本；Helm chart 会强制该拓扑。

## 响应码

| 代码                    | 含义                                                   |
| ----------------------- | ------------------------------------------------------ |
| `200 OK`                | 同步运行完成；响应体携带 `output`                      |
| `202 Accepted`          | 异步运行已启动；响应体携带 `session_id`                |
| `400 Bad Request`       | 空请求体，或无效的 `?wait=` 值                         |
| `404 Not Found`         | 未知、已轮换或已撤销的能力，或固定所有者可能已无权运行 |
| `408 Request Timeout`   | 请求体未在读取截止时间前完整接收                       |
| `413 Payload Too Large` | 请求体超过 256 KiB                                     |
| `429 Too Many Requests` | 速率限制、入站容量，或持久会话正忙于另一次运行         |
| `500 Internal Error`    | Webhook 配置无效，或会话创建失败                       |
| `502 Bad Gateway`       | Agent 运行失败                                         |
| `503 Unavailable`       | 绑定 Agent 的运行时不可用                              |
| `504 Gateway Timeout`   | 同步等待超时；运行在后台继续                           |

无效、已轮换或已撤销的能力始终返回不透明的 `404`——Stella 从不透露某个能力是否曾经存在，或它为何被拒绝。

## 限制

- **负载大小：** 每次请求最多 256 KiB；更大的请求体返回 `413` 且不会启动运行。
- **读取截止时间：** 请求体必须及时到达；停滞的上传返回 `408` 且不会启动运行。
- **速率限制：** 每个端点允许一个短暂的突发，然后是稳定的细流；持续洪泛返回 `429`。
- **入站并发：** 每个端点限制同时有多少请求正在读取请求体并被准入；超出的请求立即返回 `429`，不占用任何运行容量。
- **运行并发：** 一个端点同时最多有 10 个运行在进行；多余的触发返回 `429`，直到某个运行结束。
- **会话历史：** 临时模式下每次触发都会创建一个新会话，因此高流量 Webhook 会随时间累积会话记录。若列表变得杂乱，可在 Web UI 中清理旧会话。

## 故障排查

**收到 `404 Not Found`？**

- 该能力 URL 未知、已轮换或已撤销。请从频道的**能力端点**面板复制当前 URL，或轮换以签发新的。
- 端点所有者可能已无权运行绑定的 Agent，或所有者、Agent、频道被禁用。请恢复所有者的访问权限，或启用该 Agent/频道。
- 上一版本遗留的 `/webhooks/<channel-id>` URL 已不再有效；请使用能力 URL。

**收到 `413 Payload Too Large`？**

- 请求体超过 256 KiB。请发送更小的负载，或提供一个 Agent 可自行获取的引用。

**收到 `408 Request Timeout`？**

- 请求体未能及时上传完成。请通过更快的链路重试，或发送更小的负载。

**收到 `429 Too Many Requests`？**

- 你触发了速率限制、入站并发，或（在持久模式下）会话正忙。请降低触发频率或等待进行中的运行结束。

**同步调用返回 `504`？**

- Agent 运行时间超过了等待超时。对长时间运行的任务使用异步模式（`?wait=false`），并用返回的 `session_id` 在 Web UI 中查看运行。
