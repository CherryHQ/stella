---
title: 飞书机器人
---

Stella 内置了通过 WebSocket 连接的飞书（Lark）机器人，因此不需要公网 webhook URL。你可以在飞书中与 AI 助手对话、发送图片和文档，也可以在群聊中使用，并支持线程回复。Agent 创建的任务、目标和文章引用会渲染为紧凑的飞书卡片;配置 `STELLA_BASE_URL` 后,卡片会带一个"打开 Web UI"按钮直达对应条目。

## 前提条件

开始之前，请确保你已具备：

- 一个正在运行的 Stella 服务器（`stellad server`）
- 至少在Web UI中配置了一个 AI 提供商（如 Anthropic、OpenAI）
- 已登录飞书手机端，并且当前租户允许你创建内部应用

## 设置

1. 如果尚未启动，先启动 Stella 服务器：

   ```bash
   stellad server
   ```

2. 打开 Web UI：`http://localhost:25678`。
3. 进入 **Channels**，添加新的飞书频道实例。
4. 沿用或修改自动填好的名称。频道 ID 由 Stella 自动生成。
5. 选择这个机器人代表的 Agent。
6. 点击 **扫码创建飞书机器人**。
7. 用飞书手机端扫码，并确认创建应用。
8. Stella 会把返回的 App ID 和 App Secret 保存到频道，并启动机器人。

你可以在 Web UI 中创建多个飞书频道实例。每个实例都会获得独立的飞书 PersonalAgent 应用，也可以选择绑定专用 agent。

### 手动设置（高级）

如果你已经有飞书应用，仍然可以手动填写凭据：

1. 在 [飞书开放平台](https://open.feishu.cn/) 创建应用。
2. 在应用设置中启用 **Bot** 能力。
3. 在 **事件订阅** 中添加：
   - `im.message.receive_v1`
   - `im.message.reaction.created_v1`（可选，用于表情事件）
4. 复制你的 App ID、App Secret、Encrypt Key 和 Verification Token。
5. 在 Web UI 中添加飞书频道实例。
6. 选择这个机器人代表的 Agent。
7. 展开手动字段，输入凭据并保存。

## 自动注册用户

飞书 OAuth 与飞书聊天使用同一个规范的飞书 `union_id`。请将内置 OAuth 提供商配置为 `feishu`；随后飞书 OAuth 登录会把频道身份链接到该用户。自动注册也会创建同一对身份，因此之后的 OAuth 登录会复用该账号，而不会再创建一个。`/link` 仍可用于手动链接，且绝不会触发自动注册。

仅当你希望该机器人租户内已验证的成员首次联系时即可加入，才为对应飞书频道开启自动注册。

### 准入约定

只有同时满足以下条件时，Stella 才会创建或补全账号：

1. 此频道启用了 `auto_provision`，且事件是普通消息，而不是表情事件或 `/link` 事件。
2. 机器人有有效的租户键：显式配置的 `tenant_key`，或者启动时通过飞书租户 API 成功探测到的键。
3. 消息事件本身带有非空的 `tenant_key`，并且与该有效键完全一致。仅能访问联系人 API 不是租户成员证明。
4. Stella 能通过飞书联系人 API 读取发送者，且资料中带有非空、规范的 `union_id`。
5. Stella 中已经至少存在一个活跃管理员。

在群聊中，自动注册要求明确 `@` 提及此机器人；对未提及消息的语义路由不会注册其发送者。外部访客、缺失或不匹配的事件租户键、表情事件、联系人 API 查询失败，以及没有 `union_id` 的资料都不会创建账号。注册失败也不会阻断正常的消息处理。

联系人 API 提供规范的 `union_id`、显示名和邮箱。Stella 不会将事件中的 `union_id` 作为新的持久身份依据。它按 `union_id` 而非邮箱收敛飞书 OAuth 与频道身份；若邮箱已属于其他用户，操作会被拒绝，绝不会静默合并。

### 账号与访问行为

首次注册成功时，会以原子方式创建一个活跃的 Stella 用户、一个飞书登录身份和一个飞书频道身份。新账号始终是 `user` 角色；自动注册既不能创建管理员，也不能提升管理员权限。

若飞书未提供邮箱，Stella 会存储由规范 `union_id` 和租户键派生的稳定内部邮箱（例如 `union_id@tenant_key.feishu.local`）。它只是账号标识，不是可投递的邮箱地址。飞书 OAuth 使用相同的规范化方式，因此两个入口会收敛到同一账号。

自动注册不会分配 Agent，也不会设置默认 Agent。用户访问 Agent 时仍遵循 Stella 现有的授权和频道路由规则；绑定了专用 Agent 的频道仍按该频道的路由策略工作。

非活跃用户不会因消息而被重新激活。已有的非活跃飞书频道身份或 OAuth 身份都会被拒绝访问频道。要离职，管理员必须停用其 Stella 用户；此功能不会同步飞书通讯录中的离职事件，也不会自动移除账号。

### 所需应用权限

在飞书开放平台的 **权限管理** 中添加以下权限，以便 Stella 读取联系人 API 中的用户资料：

- `contact:user.base:readonly`
- `contact:user.id:readonly`
- `contact:user.email:readonly`（用于保存成员实际邮箱；没有该权限时 Stella 使用合成邮箱）

### 如何获取 tenant_key

登录飞书管理后台，进入 **企业信息**，找到 **Tenant Key**。

建议显式填写 `tenant_key`，这样可以避免启动时探测失败。Stella 没有有效租户键时，自动注册不会放行任何新用户。

### 配置示例

```json
{
  "app_id": "FEISHU_APP_ID",
  "app_secret": "FEISHU_APP_SECRET",
  "tenant_key": "YOUR_TENANT_KEY",
  "auto_provision": true
}
```

> **注意：** 事件必须带有与该机器人相同的租户键。共享群访客或没有该证据的任何事件都不会被自动注册。

> **注意：** 开启自动注册前先创建一个活跃管理员。该功能不能引导创建第一个管理员。

## 多用户支持

每个飞书用户都会通过平台身份自动识别。Stella 优先使用 `union_id`，对于旧链接回退到 `open_id`。飞书 OAuth 登录使用同一个 `union_id`，因此 Web UI 登录和飞书频道聊天会自动解析到同一个 Stella 用户。这使得跨多个飞书应用的多实例配置能正常工作。

会话按用户和 agent 隔离，因此不同用户拥有各自独立的记忆和默认 agent 状态。

## 流式回复

机器人通过原地编辑消息来实现流式输出：

1. 先快速发送占位回复。
2. 模型生成时持续更新内容。
3. 最终写入完整回复和耗时信息。

执行工具时的状态也会在流式消息中简要显示。

### 取消与投递

进行中的回复会带有原生 **取消** 卡片按钮。只有发起该回复的人可以取消；取消后卡片会明确显示已取消。若输入命令更方便，仍可使用 `/abort`。

Stella 会对临时的卡片回复和更新失败最多重试三次。全部失败时，会尽力把进度卡片改为投递失败提示，让你知道需要重试。群聊投递是至少一次而非恰好一次：飞书 API 结果不确定时的重试可能产生重复回复。

## 富文本卡片渲染

AI 的回复会以 [飞书卡片 JSON 2.0](https://open.feishu.cn/document/uAjLw4CM/ukzMukzMukzM/feishu-cards/feishu-cards-v2/introduction-to-feishu-card-json-structure) 格式发送，而非纯文本。这让你在飞书中获得原生排版效果。

### 支持的 Markdown 语法

绝大多数标准 Markdown 会被原样传递给卡片原生渲染：

| 语法            | 示例                  | 支持                |
| --------------- | --------------------- | ------------------- |
| 标题            | `# H1` 到 `###### H6` | 是                  |
| 加粗 / 斜体     | `**bold**` `*italic*` | 是                  |
| 删除线          | `~~text~~`            | 是                  |
| 行内代码        | `` `code` ``          | 是                  |
| 围栏代码块      | ` ```go ... ``` `     | 是                  |
| 链接            | `[text](url)`         | 是                  |
| 引用            | `> text`              | 是                  |
| 有序 / 无序列表 | `1.` / `-`            | 是                  |
| 嵌套列表        | 缩进子项              | 是                  |
| 分隔线          | `---`                 | 是                  |
| 任务复选框      | `- [x]` / `- [ ]`     | 是（渲染为 ✅ / ☐） |
| 图片            | `![alt](img_key)`     | 部分（见下文）      |

### 表格

GFM 表格会被渲染为飞书原生表格组件，支持完整分页，没有行数限制。列对齐方式（`:--`、`:-:`、`--:`）会保留。每张卡片最多 5 个原生表格，超出的会回退为代码块格式。

### 交互按钮

Agent 可以在回复中使用双花括号语法嵌入可点击的按钮，格式为：

<pre>{'{{'}button value="retry" type="primary" label="重试"{'}}'}</pre>

| 属性      | 必填 | 说明                                 |
| --------- | ---- | ------------------------------------ |
| `value`   | 是   | 点击时回传的回调标识                 |
| `label`   | 是   | 按钮显示文本                         |
| `type`    | 否   | 样式：`default`、`primary`、`danger` |
| `confirm` | 否   | 点击前弹出的确认对话框文本           |

点击按钮后，Stella 会将操作以消息形式转发给 agent（如 `[User clicked: retry]`），由 agent 在上下文中决定后续行为。点击后会立即显示 toast 提示（"Processing..."），agent 处理期间不需要等待。

连续多个按钮会水平排列为一行，单独的按钮占满整行。

### 已知限制

- **图片需要飞书 image key。** `![alt](img_key)` 语法仅在图片源是通过飞书 API 上传后获得的 `img_key` 时才生效。外部 URL（如 `https://example.com/photo.png`）会被飞书静默忽略。图片上传功能尚未实现。
- **Markdown 中的 HTML 标签**（如 `<font>`、`<text_tag>`）会被透传但不做校验。仅在确认飞书卡片渲染器支持时才建议使用。

## 支持的消息类型

| 类型            | 行为                                                              |
| --------------- | ----------------------------------------------------------------- |
| 文本            | 作为普通文本发送给模型                                            |
| 图片            | 下载并保存到你的 assets 目录后作为多模态输入发送                  |
| 富文本 Post     | 解析为文本加图片；图片保存到你的 assets 目录后作为多模态输入发送  |
| 音频            | 转成带时长的描述文本                                              |
| 视频            | 转成带时长的描述文本                                              |
| 文件            | 下载并保存到磁盘；图片作为多模态输入，其他文件附带 xberg 提取提示 |
| 表情贴纸        | 转成描述文本                                                      |
| 位置            | 尽量附带坐标信息的描述文本                                        |
| 分享的群聊/用户 | 转成描述文本                                                      |
| 合并转发        | 转成摘要标记                                                      |

## 原生线程

如果你在飞书线程中发消息，Stella 会在线程内回复，并将群聊上下文绑定到该线程根消息。线程外消息仍然使用父聊天会话。每个线程在收到第一条消息时都会独立初始化，不会悄悄回退到父聊天的上下文。

## 群组行为

群聊默认关闭，需要在 Web UI 中打开**允许群聊**。打开后，机器人被拉进的所有群聊都可以使用；关闭时所有群消息都会被拒绝，也不会建立群成员关系。

群消息默认必须 @机器人。关闭**必须 @机器人**后可以使用 Stella 的语义群聊路由。机器人所在群聊的每位成员都能联系绑定的 Agent，因此请通过「谁能把机器人拉进群」来控制访问。

你也可以通过 `groups` 字段为特定群单独覆盖配置。

## 访问控制

**允许私信**控制私聊、账号关联和私聊触发的自动开通。已关联的 Stella 用户继续使用自己的普通 session 和权限。

未关联的私聊发送者默认会被拒绝。只有在你希望未自动开通或未关联的用户通过持久、受限的访客 session 使用渠道绑定的 Agent 时，才启用**允许访客私信**。访客历史会持久保存和压缩，但没有 profile、reflection、工具、skills、文件、workspace、plugins 或 delegation。访客只能使用 `/link`、`/help`、`/new`、`/compact` 和 `/abort`；附件会在下载前被拒绝，关联账号也不会合并此前的访客历史。

系统会限制每位访客的消息速率和每个渠道的持久访客数量，并在配置的保留期后删除不活跃访客及其 session。公开访客访问仍可能产生模型费用和滥用风险。请使用专用且对访客安全的 Agent，并确保其 base prompt 不含 secret。

## 命令

飞书支持标准聊天命令：

| 命令       | 说明                                     |
| ---------- | ---------------------------------------- |
| `/new`     | 开始新会话（此前的历史退出记忆搜索）     |
| `/compact` | 就地压缩当前会话（同一会话，上下文更短） |
| `/abort`   | 取消正在进行的响应                       |
| `/whoami`  | 显示你的平台身份                         |

`/new` 仅在私聊中生效。群聊的上下文由所有成员共享，因此在群里输入 `/new` 只会回复共享会话无法重置，不会改变任何内容；该命令本身也不会进入群聊历史。新会话保留哪些内容，见[记忆](/docs/guides/memory)。

## 配置参考

```json
{
  "app_id": "FEISHU_APP_ID",
  "app_secret": "FEISHU_APP_SECRET",
  "encrypt_key": "",
  "verification_token": "",
  "enable_notify": false,
  "tenant_key": "",
  "auto_provision": false,
  "allow_group": false,
  "allow_dm": true,
  "allow_unlinked_dm": false,
  "guest_message_limit_per_minute": 10,
  "guest_max_per_channel": 1000,
  "guest_retention_days": 30,
  "require_mention": true,
  "groups": {
    "oc_example": {
      "system_prompt": "这个群里请作为基础设施助手回复。"
    }
  }
}
```

| 字段                 | 说明                                                               |
| -------------------- | ------------------------------------------------------------------ |
| `app_id`             | 飞书应用 App ID                                                    |
| `app_secret`         | 飞书应用 App Secret                                                |
| `encrypt_key`        | 可选的事件加密密钥                                                 |
| `verification_token` | 可选的事件校验 token                                               |
| `enable_notify`      | 允许调度器和 `notify` 输出发送到飞书                               |
| `tenant_key`         | 企业 Tenant Key。可选：Stella 可在启动时自动探测，但仍建议显式配置 |
| `auto_provision`     | 仅为已验证租户成员创建账号：私聊消息，或明确 @提及此机器人的群消息 |
| `allow_group`        | 接受机器人所在飞书群聊的消息；默认为 `false`                       |
| `allow_dm`           | 接受私聊、账号关联和私聊自动开通；默认为 `true`                    |
| `allow_unlinked_dm`  | 允许未关联私聊发送者使用受限访客 session；默认为 `false`           |
| `require_mention`    | 在群聊中要求 @机器人；默认为 `true`                                |
| `groups`             | 按飞书 `chat_id` 配置的群级覆盖项                                  |

访客限制使用 `guest_message_limit_per_minute`（默认 `10`）、`guest_max_per_channel`（默认 `1000`）和 `guest_retention_days`（默认 `30`）。

`allow_group` 取代了原来的 `allowed_chat_ids` allowlist。升级时，原先至少填写了一个 `chat_id` 的渠道会继续服务群聊（`allow_group` 置为 `true`）；列表为空或不存在的渠道保持关闭。请注意范围会变大：开关无法表达「只允许这几个群」，升级后机器人所在的**所有**群都能触达 Agent，而不只是原先列出的那些。飞书会在启动时为这些群全部建立群成员关系，因此升级后请检查机器人的群成员关系；如果你原本依赖 allowlist 把某个群挡在外面，请关闭该开关。

## 故障排除

**机器人不响应消息？**

- 确保 `stellad server` 正在运行，且飞书频道已在Web UI中配置。
- 确认你的 App ID 和 App Secret 是否正确。
- 检查是否在飞书应用中添加了 `im.message.receive_v1` 事件订阅。

**机器人在群组中不响应？**

- 最可靠的触发方式是 @提及机器人。
- 打开**允许群聊**。它默认关闭，会拒绝所有群消息。
- 如果你期望无 @提及也能回复，确认至少一个群内 agent 配置了可用于路由的模型，并且消息是明确请求而不是闲聊。

**自动注册未创建用户？**

1. 确保在正确的飞书频道实例上启用了自动注册 —— 这是按实例配置的，不是全局开关。
2. 在群聊里，首次注册必须让用户 @提及此机器人。未提及消息即使被语义路由选中，也不会自动注册发送者。
3. 确认 `tenant_key` 是否已配置，或启动时自动探测是否成功；并确认消息事件带有完全相同的租户键。任一检查失败都会跳过自动注册。
4. 确认飞书应用具备以下权限：`contact:user.base:readonly`、`contact:user.id:readonly`；如需保存成员实际邮箱，还应配置 `contact:user.email:readonly`。
5. Stella 中必须至少存在一个管理员。全新部署在第一个管理员创建前会拒绝自动注册。
6. 外部访客不会被自动注册，只有内部租户成员才符合条件。
7. 修改配置后请重启 `stellad server`。

一个可靠的自动注册配置如下：

```json
{
  "app_id": "FEISHU_APP_ID",
  "app_secret": "FEISHU_APP_SECRET",
  "tenant_key": "YOUR_TENANT_KEY",
  "auto_provision": true
}
```

语义路由仍可能让闲聊保持静默；如果要稳定触发首次联系和自动注册，请让用户 @提及机器人。

**图片或文件未被分析？**

- 在 **设置 -> 视觉** 配置普通会话的图片基线。声明 `text, image` 的模型只在当前回合接收像素；没有已存基线的群组历史使用不可用标记。
- 文件上传需要为活跃 agent 启用 Xberg skill。

**通知不工作？**

- 在频道配置中将 `enable_notify` 设为 `true`。
- 确保机器人已与目标用户或群组有过对话。
