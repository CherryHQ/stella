---
title: 微信机器人
---

Stella 内置了一个通过 iLink Bot API 长轮询连接的微信机器人 —— 无需公网 URL。你可以在微信中与 AI 助手对话、发送图片和文件进行分析，也可以接收通知。

## 前提条件

开始之前，请确保你已具备：

- 一个正在运行的 Stella 服务器（`stellad server`）
- 至少在Web UI中配置了一个 AI 提供商（如 Anthropic、OpenAI）
- 一个微信账号，用于扫码创建机器人
- 一个已启用的 Stella Agent，用来接收这个机器人的消息

## 设置

1. 如果尚未启动，先启动 Stella 服务器：

   ```bash
   stellad server
   ```

2. 打开Web UI `http://localhost:25678`。
3. 进入 **Channels** 页面，点击 **New Channel**。
4. 选择 **Weixin**，沿用或修改自动填好的名称，并选择接收这个机器人消息的 Agent。微信是单例频道：频道 ID 始终是 `weixin`。
5. 点击 **扫码创建微信机器人**。
6. 在手机上打开微信，扫描二维码并确认创建机器人。
7. 确认后，Stella 会保存返回的 iLink 凭据并启动频道。

所有频道配置都通过Web UI管理。微信在 Stella 中是单例频道，因为一个 iLink 账号不支持多个独立机器人。如果你已经有 iLink 凭据，展开 **我已有微信 iLink 凭据** 后手动填写。

## 工作原理

微信频道使用 iLink Bot 协议。扫码登录后，Stella 会获得一个 `bot_token`，用于后续所有 API 调用。消息通过长轮询接收，响应通过同一 API 发送。

### 会话过期

如果 iLink 会话过期，微信频道会停止响应。你可以重新扫码创建机器人，或用新的手动凭据更新频道。

## 多用户支持

每个微信用户会从其 iLink 用户 ID 自动识别。会话按用户和 agent 分别管理。无需手动设置用户。

## 消息

机器人发送和接收的文本消息有 2000 字符的限制。超过此限制的消息会在段落、换行或空格处自动分割。

### 图片支持

你可以向机器人发送图片进行分析。图片会被下载、解密、保存到你的私有 assets 目录，并作为多模态内容传递给 AI 模型。

机器人也可以发送图片。生成的图片会被加密、上传，并作为图片消息发送。

### 文件支持

你可以向机器人发送文件。文件会被下载、解密、保存到你的私有 assets 目录；图片类文件会直接作为多模态输入传给模型，其他文件附带 xberg 提取提示，agent 随后可使用 `xberg extract` 命令解析文件内容。视频消息会被记录但跳过处理。

### 输入指示器

当助手处理你的消息时，你会看到输入指示器。指示器每 5 秒刷新一次，直到响应就绪。

## 访问控制

你可以在Web UI的"允许的 ID"字段中添加 iLink 用户 ID 来限制哪些微信用户可以与机器人交互。留空则允许所有用户。使用 `/whoami` 命令获取你的用户 ID。

## 命令

将这些命令作为文本消息发送给机器人：

| 命令                | 描述                                     |
| ------------------- | ---------------------------------------- |
| `/start` 或 `/help` | 欢迎和帮助信息                           |
| `/new`              | 开始新会话（此前的历史退出记忆搜索）     |
| `/compact`          | 就地压缩当前会话（同一会话，上下文更短） |
| `/abort`            | 取消正在进行的响应                       |
| `/whoami`           | 显示你的用户 ID 用于配置                 |

`/new` 仅在私聊中生效。群聊的上下文由所有成员共享，因此在群里输入 `/new` 只会回复共享会话无法重置，不会改变任何内容；该命令本身也不会进入群聊历史。新会话保留哪些内容，见[记忆](/docs/guides/memory)。

## 通知

微信频道支持通知（调度器结果、notify 工具）。在Web UI中设置"启用通知"并配置"通知聊天"的用户 ID。

**重要限制**：通知需要一个缓存的 token，该 token 仅存在于内存中。重启 `stellad server` 后，向微信用户发送通知会失败，直到他们发送一条新消息。这是 iLink 协议的已知限制。

## 配置参考

以下所有设置都通过Web UI管理。

| 字段          | 描述                                          | 默认值   |
| ------------- | --------------------------------------------- | -------- |
| `bot_token`   | iLink bot token（通过扫码配置或手动配置获取） | （必需） |
| `base_url`    | iLink API 基础 URL                            | （自动） |
| `bot_id`      | iLink bot ID（通过扫码配置获取）              | （自动） |
| `user_id`     | iLink 用户 ID（通过扫码配置获取）             | （自动） |
| `notify_chat` | 默认通知用户 ID                               | `""`     |
| `allowed_ids` | 允许交互的用户 ID（空 = 所有人）              | `[]`     |

## 故障排除

**机器人不响应消息？**

- 确保 `stellad server` 正在运行，且微信频道已在Web UI中配置。
- iLink 凭据可能已过期。进入Web UI重新执行扫码配置。

**会话过期了？**

- 当 iLink 会话过期时，重新执行 **扫码创建微信机器人**，或填写一组新的手动凭据。

**通知无法送达？**

- 微信通知需要接收者先向机器人发送过消息（这样 Stella 才有缓存的 context token）。
- 重启 `stellad server` 后，所有用户需要至少发送一条消息才能再次接收通知。

**图片或文件未被分析？**

- 在 **管理 -> 模型** 配置图片基线。声明 `text, image` 的模型只在当前回合接收像素。群图片在第一次被读取的那个回合描述一次并存下来；没有可用的基线模型时，历史里才显示不可用标记。
- 文件分析需要为活跃 agent 启用 Xberg skill。

**消息被截断？**

- 微信每条消息有 2000 字符的限制。Stella 会自动分割较长的响应，但非常长的工具输出可能会被截断。
