---
title: 钉钉
description: 使用 Stream 模式企业机器人将 Stella 接入钉钉。
---

通过钉钉企业机器人，在单聊和受信任的群聊中使用 Stella。Stella 采用钉钉 Stream 模式，因此不需要公网回调地址。

## 创建机器人

1. 打开[钉钉开发者后台](https://open-dev.dingtalk.com/)，创建企业内部应用。
2. 为应用添加**机器人**能力。
3. 将机器人的消息接收模式设置为 **Stream 模式**。
4. 将应用发布到你的组织。
5. 复制应用的 **Client ID** 和 **Client Secret**。

## 连接 Stella

1. 打开 Stella Web UI，进入**渠道**。
2. 添加一个**钉钉**渠道。
3. 填入 Client ID 和 Client Secret。
4. 如果要在群聊中使用，将渠道绑定到一个已启用的 Agent。
5. 启用并保存渠道。
6. 在钉钉中给机器人发送一条单聊消息。

如需把钉钉身份关联到已有 Stella 账号，请在 Stella 个人资料中生成关联码，然后向机器人发送 `/link 关联码`。

## 允许群聊

群聊访问默认关闭：所有群消息都会被拒绝，单聊不受影响。

1. 在渠道设置中打开**允许群聊**并保存。
2. 把机器人加入钉钉群，并 @机器人。

钉钉只会把发给机器人的群消息推送给应用。除非你的钉钉应用有明确的其他回调需求，否则请保持**必须 @机器人**开启。

## 已支持

- 单聊文本消息
- @机器人的群聊文本消息
- `/link`、`/help`、`/new`、`/compact`、`/abort` 等公共渠道命令
- 每位已关联钉钉用户独立的 Stella 身份和记忆
- 通过钉钉会话 Webhook 发送最终文本回复
- 最近收到的会话 Webhook 仍有效时发送通知

## 限制

- 当前仅处理文本消息，暂不接收或发送钉钉图片、文件、语音、视频、富文本和互动卡片。
- 钉钉会话 Webhook 是临时凭证，且只保存在内存中。Stella 重启或 Webhook 过期后，主动通知会失败，直到该用户或群再次向机器人发消息。普通回复不受影响，因为每条入站消息都会携带新的 Webhook。
- Agent 完成后才会发送回复，钉钉中暂不显示逐 token 输出。

## 故障排查

**渠道无法启动：**确认应用已发布、Client ID 和 Client Secret 属于同一个应用，并且机器人消息接收方式已设置为 Stream 模式。

**单聊没有回复：**开启**允许私信**，然后确认钉钉身份已关联；如需访客访问，应将渠道绑定到不含敏感信息的专用 Agent，并显式开启访客私信。

**群聊没有回复：**确认消息中 @了机器人、渠道已绑定到已启用的 Agent，并且 allowlist 中包含完全一致的 `conversation_id`。

**重启后通知失败：**先给机器人发送任意一条单聊消息以刷新临时会话 Webhook，再重试通知。
