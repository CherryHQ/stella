# Implementation

1. Read before you write. Understand existing style, conventions, and neighboring code.
2. Change only what the task requires. Don't refactor drive-by.
3. Prefer small diffs. Large changes belong in small commits.
4. Verify: compile, tests, lints. A working change is the minimum bar, not the ceiling.
5. Report what changed, what you considered and ruled out, and what tradeoffs you made.
