## 一、先决决断(动工前拍板,不拍板不写网关代码)

**D1 · 首动作类封路的残余问题(机制部分已被 #767 消解)。** #767 POC 已同时给出:首动作 = Bitable record update(岗位自主权限,不依赖人类确认)、独立岗位自有凭证从第一天就不进沙箱、参数绑定一次性审批也纳入 v0——原先"A 前移 / B 改选"的二选一不复存在。**残余的经验问题只剩一个**:legacy 报销 skill 手里的宽权限 Bitable token 能否**收缩掉**已迁移动作类的权限(飞书凭证粒度是否支持)。收不掉,legacy token 本身就是绕行通道,封路验收(#767 §10"同凭证不得在网关外使用")不成立,须把该 token 覆盖的全部调用一并迁入网关。E3 spike 验证,结论进 #767 评论区。

**D2 · #719 收窄执行。** 结论已有(见上表),差一个动作:改标题、正文加边界声明。5 分钟,随 E3 一起做。

**D3 · milestone。** 现无 Q1/雇佣主题 milestone,建议新建 `employment Q1`(due 2026-10-31),E1–E13 全部挂入;E15 挂 `k8s deployment`。

**D4 · #766 的 Q1 前移提议(待 V 拍板)。** #766 §13 主张 Tool Package v0 + Action Catalog v0 进 Q1 地基。冲突:roadmap v3.2 把 manifest/Pack 排在 Q2/Q3,Q1 只要求"报销 skill 接入网关"。#766 v0 是一整个新域(七张表、签名、审查激活、无凭证执行器沙箱、目录快照与精确失效),且执行器沙箱的干净实现依赖 #768——进 Q1 会压垮关键路径。建议:**维持 v3.2 排期**。Q1 用一个编译期的报销专用工具接网关(核心出现一个业务专名,显式标记为契约债,记入 E7 issue);Q2 HR 员工入职时 #766 落地并回收这笔债——这正好让 Q2"核心零业务专名"闸门有真实的清偿动作可查。#767 已声明 typed 路径可以直连 host 侧 Provider Adapter,不等包机制,此路线与其兼容。

- 每个 issue 建立即挂项目板 #14 与 milestone;What/Why/How/Refs 模板,Refs 回指 roadmap 章节与 capability-gap 编号。
